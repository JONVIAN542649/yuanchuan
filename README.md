# 原传

个人使用的 Windows / Android 局域网原文件互传工具。两端在不同网络（手机流量）时自动经自建加密中继完成配对与传输。无账号、无注册、无云端服务，只保留设备、传输记录和设置三个页面。

## 0.4.1 优化要点（性能 / 路径 / 同步安全 / 工程）

- **传输性能**：发送端流水线窗口满才 `flush`（不再每块刷盘）；`SocketReader` 改为连续读缓冲；接收端边写边算 SHA-256（少一次整文件读盘）；哈希与建连并行。原生 AES（Windows CNG / Android 硬件）本轮**有意推迟**：须保持 X25519+HKDF+AES-GCM 跨端字节兼容，单独专项再换。
- **路径与发现**：直连与中继短超时并行竞速，记住上次成功路径；发现广播按网卡真实前缀算定向广播（不再死假定 `/24`）；中继 `LISTEN` 按行缓冲，避免 TCP 粘拆包丢 `INCOMING`。NAT 打洞仍为后续可选项，本轮未做。
- **自动同步与安全**：可选择并持久化默认同步目标（多台电脑不再误发到第一台）；剪贴板用内容哈希去重且不落盘明文；下载文件等大小稳定再发；6 位设备码配对需确认并绑定对端公钥（单次有效）；更新包安装前校验 SHA-256（含 Windows 脚本复验）。
- **工程**：传输历史改为独立 JSON 文件 + 防抖写入，不再每秒刷 SharedPreferences。

## 0.4.0 升级要点（2026-11-19 四条需求）

- **手机传电脑又稳又快**：AES 加解密搬进 4 核 isolate 池 + 收发双端流水线（修前回环 2.4 MB/s → 修后 7.8 MB/s，同进程最坏口径；真机双端各自有池，实际更快）；TCP_NODELAY 全链路；Android 传输服务持有高性能 Wi-Fi 锁（锁屏不再休眠断连）；重试 2/3/5/8/15 秒退避、连续 8 次封顶；直连成功即复位路径择优计数（不再被临时抖动钉死在中继上）。
- **聊天框变成真聊天**：文字、图片、文件全在聊天框互传（气泡+图片内联预览+进度/速率/剩余时间），接收自动入库免手动确认（设置里"接收前询问"可改回手动）；聊天记录按设备本地持久化（各保留 300 条）；底部"传输"页已并入聊天页。
- **托盘退出修复**：托盘 isolate 改事件驱动（旧实现 sleep 死循环收不到退出命令），退出前先删图标并回收 Win32 资源；退出链路 1 秒保底超时 + `exit(0)` 必达，右键退出 2 秒内进程消失。
- **手机自动同步到电脑**（新功能，Android）：前台剪贴板文字（默认开）、下载目录新图片（默认开）、下载目录新文件（默认关，防流量意外）自动以聊天消息（标注来源）发到电脑；去抖去重（同一内容只发一次）、断连自动积压（上限 50）重连补传；设置里逐项开关。

## 0.3.0 升级要点（对标 LocalSend / Quick Share / SHAREit / PairDrop 取其精华）

- **批量单连接**（LocalSend 精华）：一批文件共用一条加密连接逐个接力，不再每个文件重新握手；任一文件断线只重连它自己。
- **流水线分块**：1 MiB 分块、最多 8 块在途不等逐块确认（对标 LocalSend 的 HTTP 流式传输），中继跨网链路吞吐不再受往返延迟卡死；旧版本对端自动协商退回逐块确认。
- **速率与剩余时间**：传输卡片实时显示 x/s 与“剩余 n 分 n 秒”，传输页顶部有总速率条（SHAREit 式）。
- **接收前询问**（Quick Share 精华）：设置可开“接收前询问”，每个新会话弹窗确认、60 秒不回应自动拒绝；同会话批量只问一次。默认关闭，保持个人工具的零打扰。
- **反向配对**（PairDrop 精华）：手机也能“本机显示配对码”，电脑在配对弹窗里输入对方的 6 位设备码即完成配对（局域网直连、跨网走中继），配对方向不再固定。
- **修复**：零字节文件此前会被误判“文件为空”，现在可正常发送并校验。


## 使用

1. 电脑和手机连接同一个局域网（同一 Wi-Fi，或一端开热点另一端连上），分别打开“原传”。
2. Windows 首次启动时，如系统弹出防火墙提示，请在“专用网络”上允许原传通信。
3. 配对两种方式任选：电脑“设备 → 显示配对码”后手机扫码；或手机“扫码配对 → 手动输入设备码”，填电脑 IP、端口和 6 位设备码。配对二维码包含电脑全部候选地址，手机会并发尝试，多网卡也能配对成功。
4. 配对只需一次。以后打开两端应用会自动发现；也可先选择文件排队，设备上线后自动尝试传输。
5. 在设备卡片上选择“传文件”或“传文件夹”。传输页可查看进度、暂停、继续和取消。
6. 接收端暂停后，在发送端点击“继续”即可从断点恢复。

## Windows 悬浮窗

- 设置页可在三种形态间切换：完整窗口 / 小窗 / 悬浮条（200×56 圆角长条，置顶、可拖动、位置记忆）。
- 把文件或文件夹拖到悬浮条或小窗上即发送；多台设备在线时弹窗选择目标。
- 悬浮条状态收到文件会出现红色数字角标；点击悬浮条直接把这些文件复制到剪贴板（支持多个、混合类型），资源管理器 Ctrl+V 粘贴。
- “设置 → 悬浮窗 → 开机自启动”写入当前用户注册表 Run 键，登录后直接进入悬浮条形态。

## 固定接收位置

- Windows：系统“下载”目录下的 `YuanChuan`。
- Android：`内部存储/Download/YuanChuan`。

同名文件自动添加 ` (1)`、` (2)` 等序号，不覆盖已有文件。未完成的接收数据保存在接收目录的 `.incoming` 中。

## Android 首次设置

- “设置 → 接收文件”中授予“所有文件访问”权限，用于把任意类型文件直接写入固定下载目录。
- 传输期间会显示前台服务通知。等待时释放 CPU 唤醒锁，实际传输时才持有。
- 部分手机系统会限制后台活动。若锁屏后系统强制结束应用，请在系统设置中允许“原传”后台运行或关闭针对它的电池优化；重新打开后可继续传输。
- Android 系统自身的前台服务和省电策略仍可能影响超长任务，不能绕过系统限制。

## 原样与完整性

- 不设置文件格式白名单，不压缩、不转码图片或视频。
- 发送前流式计算源文件 SHA-256；接收完成后重新计算并比对。
- 校验不一致不会生成“已完成”文件。
- 文件以 1 MiB 原始二进制分块发送，最多 8 块流水线在途（旧版对端自动退回逐块确认）；同一批文件共用一条加密连接接力。已配对设备使用 X25519、HKDF-SHA256 和 AES-GCM 建立加密连接。
- 不设置人为文件大小上限，实际可用大小受剩余存储空间、文件系统和移动设备系统限制。

## 开发与构建

本项目的已验证环境：Flutter 3.50.0、JDK 17、Android SDK 36、Gradle 9.5.0、AGP 9.3.1、Kotlin 2.4.20；Windows 还需要 Visual Studio 2022 的“使用 C++ 的桌面开发”工作负载。

```powershell
flutter pub get
flutter analyze
flutter test
flutter build apk --release
flutter build windows --release
```

Android 包名为 `dev.localfiles.drop`。当前个人版本的 release 构建使用 debug 签名，便于直接安装；如要长期升级安装，请保留同一个签名配置，或改为自己的正式签名。

## 验证范围

源码包含真实 socket 集成测试，覆盖任意二进制内容、SHA-256、断点续传、零字节文件、同名防覆盖、错误哈希、暂停、取消、暂时断线后的自动重试，以及拖入路径转传输条目。实际测试与构建结果以交付时附带的验证记录为准；真机扫码、锁屏和厂商后台策略需要在目标设备上复核。
